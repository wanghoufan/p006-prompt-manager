## 七、给主会话的定位线索（仅事实推断方向，非结论）

两轮证据指向同一矛盾：

1. **今天的数据在服务端和 localStorage 双双不存在**（源头就没持久化）。
2. **干净操作下 legacy 保存不丢**（POST /api/sync 全程 200，刷新后标题/标签均在）。

最可能的根因方向：**用户当时触发了某种会清空 / 覆盖写队列的路径**（昨晚的 30s 超时修复是否完整生效、写队列在超时后是否丢弃了未落盘项），而非「保存链路本身坏掉」。建议下一轮：

- 重点抓「写队列超时 / 重试」路径，或复现写队列停摆场景（参考 BUGS.md 中「并发冲突验收」里记录的「写队列停摆」观察）。
- 询问用户当时的精确操作步骤与报错提示。
