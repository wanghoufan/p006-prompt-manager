## A. 当前产品真实形态（它最后变成了什么）

### 一句话

一个本地网页端的**提示词知识库 + Agent 调取接口**：把散落在聊天记录、备忘录、Notion、txt 里的常用提示词沉淀成可检索的卡片，复制即统计，登录后多端实时同步，并能通过 MCP 让 WorkBuddy / Codex 等 AI 用一句「调取 xxx」把任意卡片正文作为系统提示词直接执行。

当前真实规模：云端约 54 张卡（53 张真实 + 1 张保留测试卡），Docker 单容器 `prompt-manager-prompt-manager-1` 绑定 `0.0.0.0:3100`，固定访问 `http://192.168.31.60:3100`。

### 核心目标

解决四个真实痛点（README 原话）：提示词散落各处复用时找不到；每次切换 AI 角色都要重贴一大段系统提示词；电脑 A 整理的提示词电脑 B 看不到；哪个提示词最常用没有数据支撑。

最终结果：粘贴正文 → AI 自动提炼标题/标签 → 一键复制（统计次数）→ 多端实时同步 → 给常用卡设短调取码 → 在 Agent 里说一句即按该角色开工。

### 完整使用过程（按真实顺序）

1. **什么时候打开**：每天要用 GPT / Agent 干活前，或刚写出一条好用的提示词想存下来时。Mini 单设备日常使用为主。
2. **第一件事**：顶部输入框（Composer）粘贴提示词正文。默认直接建卡，后台自动调用 AI 生成标题与标签；失败时可重试或直接创建空白卡。
3. **接下来**：卡片出现在网格（大屏 3 列，标题 + 2 行正文预览 + 标签 + `@code` 徽标 + 星级 + 复制次数）。点卡片选中（键盘 1–5 打星、0 清除），双击或点编辑进入详情/右侧预览面板。
4. **整理**：标题（≤20 字计数）、标签（flomo 风格 TagEditor：输入 `#标签名` 回车或空格即加为 chip，下拉补全点选，chip 上 × 移除，最多 3 个，达上限红色提示）、调取码（英文/数字/短横线 ≤12 字符，`x/12` 计数，冲突实时红字）、备注（正文上方 2 行可拖动，自填何时用/注意事项，停手 700ms 自动存）、星级。
5. **使用**：点「复制」写入剪贴板并计数 +1；或在 WorkBuddy / Codex 新会话说「调取 jbyj」，MCP 经云端 RPC 取正文注入并同样计数 +1。
6. **查找**：SortBar 搜索框（300ms 防抖，标题/正文/标签/调取码/备注大小写不敏感，`@code` 直达仅按调取码，高亮 `<mark>`，显示命中 x / 共 y，刷新即清）+ 左侧标签树单选筛选（再点取消，含子标签，数量排序，完整路径搜索，无标签入口）+ 排序（最近更新 / 复制次数 / 评分；搜索激活时按相关度标题 4 > 调取码·标签 3 > 备注 2 > 正文 1）。
7. **修改**：标题/标签/调取码/备注/星级失焦即存（腾讯文档/飞书式，底部「已自动保存」角标）；正文失焦仅保存不建版，手动保存或 `Ctrl/⌘+Enter` 才生成版本快照（最多 10 版，可 diff、可回滚，回滚不新增版本）。
8. **回顾**：版本历史展开看 LCS 行级 diff；思维方式总结（AI 分析框架与技巧，100–200 字，缓存在卡片上，可重生成，可自定义模板）。
9. **备份**：导出全量 JSON / Markdown（含调取码、版本、备注），导入整体恢复（带 skipped 字段级原因，Toast 可滚动 6s 展示）；定期导出 + `DockerBackups/prompt-manager/` 云端 dump 三件套。

### 功能分层（为什么存在）

**核心功能（没有就不算可用）**

- 卡片增删改查 + 删除确认/撤销：新建（粘贴建卡）、编辑（失焦自动保存）、单卡删除（网格 hover 红色删除，按设置决定是否二次确认，删除后自动取消选中）、清空仓库、删除 10s 撤销。
- AI 自动标题/标签：不做则每卡都要手工想标题贴标签，入库成本太高没人坚持用。
- 复制即统计（含 MCP 共用计数 + 清零）：回答"哪个提示词真有用"，排序依据。
- 全局搜索 + `@code` 直达 + 标签筛选 + 三档排序：50 张以上时没有检索只能一条条翻，产品即死。
- 版本（10 版上限 + 回滚 + diff）：提示词是反复打磨的，没有版本不敢改。

**高频功能（每天都用）**

- 失焦自动保存 + 关闭/切卡不丢稿（Esc/蒙层/抽屉收起前 flush，备注防抖 cleanup）：消灭"忘记点保存"。
- 打星评分（点击 + 键盘）：比复制次数更主观的"质量分"。
- 备注字段：存"这条什么时候用、有什么坑"，AI 生成不了，只能自填。
- 思维方式总结：把一条好提示词的方法论沉淀下来，比正文本身更值钱。
- 格式规范化（保存自动左对齐、去多余空行）+ 去重 confirm（内容全等命中提示标题 X 是否仍要添加）：保持库干净。

**辅助功能（有了更顺手）**

- 双主题（跟随系统/暗/亮，首屏防闪烁，system 实时跟随）、搜索高亮双主题自适应（WCAG AA）、Composer 粘贴长文自适应 6 行、右侧面板可拖宽（320–720px，双击重置）、移动端底部抽屉（`<md` 时）、空/离线横幅三态、导入详情、撤销栈、批量管理（多选 checkbox + 打标签/打星/导出/删除/取消）。
- 示例知识库（12 张只读示例，一键载入/清空）：新用户第一次打开不至于面对空库发呆。

**管理功能（管库的人用）**

- 标签体系：ID 解耦（tags + prompt_tags）、树形（父/子/孙、拖拽排序/设为子标签/合并、循环与同父重名检测）、重命名自动修正所有关联卡、删除双模式（仅删自身子标签提升 / 删整棵子树，绝不删 Prompt，删除前展示影响数 N 条+子标签名，10s 撤销）、当前标签下新建继承首位、服务端五项校验 + 客户端自愈。
- 设置：思维总结模板自定义、删除前二次确认开关、外观主题、AI 服务（8 厂商切换）、MCP 云端访问（令牌生成/撤销/复制兜底）。
- MCP 调取码体系：短码规则、冲突红字、徽标展示、MCP 工具 `prompt_manager_activate_prompt`。

**后来补出来、但本该一开始就考虑的功能**

- 单卡删除（产品报告 v1 头号缺口：只能清空全库，废卡永久污染）、搜索（PRD §9 曾明确不做，30+ 卡即崩）、跨设备同步、调取码 + MCP、标签树治理（重命名/移动/删除/合并/撤销/校验）、自动保存与丢稿保护、版本节流（失焦不建版）、批量管理、移动端抽屉、主题。

### 体验特点

- 布局：左标签树 + 右卡片网格 + 右侧正文优先预览面板（标题→备注→标签→正文，正文占约 80% 纵向，思维总结/版本默认折叠）。
- 操作逻辑：选中→预览→详情三级；高频操作（复制、打星、搜索、删卡）1–2 步；危险操作 confirm + 10s 撤销双保险。
- 默认行为：粘贴即建卡、失焦即存、正文失焦不建版、搜索刷新即清、筛选态新建继承当前标签首位。
- 空状态/错误：仓库空引导（双击进入详情 · 拖动调宽 · 选中打星）、搜索 0 命中引导、离线 rust 横幅 + 重试、云端暂时不可用横幅 + 退避重试、冲突 toast 明示刷新再改、调取码冲突红字常驻。
- 桌面/移动：桌面 3 列网格 + 可调宽侧栏；`<md` 预览变底部抽屉（`max-h-[75dvh]`）保证核心编辑不断。

### 数据与同步现状（技术事实，用户视角翻译）

- 登录后主数据在 Supabase 云端独立 `prompt_manager` Schema（6 表：cards / card_versions / tags / prompt_tags / settings / mcp_access_tokens；RLS 每表 4 策略；Realtime 订阅 5 表约 3 秒互推；记录级 revision 条件更新保证并发不静默覆盖；owner 归属隔离）。
- 登录方式：Magic Link + Google OAuth PKCE，必须用 `http://192.168.31.60:3100`（localhost/`.local` 因白名单/代理问题不可用）。
- 未登录时才走旧链路（`data/store.json` + `/api/sync` + localStorage + SSE），长期保留只读兼容。曾有退场草稿，2026-09-04 用户最终裁定取消。
- MCP：子包直连云端 `activate_prompt` RPC，每设备独立可撤销令牌（库内只存 SHA-256 哈希），命中原子 `copy_count+1`。
- 写队列 30s 单项超时 + 自动重试（PM-3）：某个请求卡死不再永久堵住后面所有保存。
- AI：8 厂商可切换（DeepSeek/智谱/腾讯/豆包/Kimi/Google/OpenAI/OpenRouter，默认 opencode-go），服务端代理密钥不暴露浏览器；但多厂商 Key 回退、模型写死列表、报错文案仍有 P1 待办（见 PRODUCT_BACKLOG，未阻塞运行）。

## C. 如果重新开发，Day 1 就应该明确什么

1. **人 vs 设备**：就我一个人用还是以后可能两人看？一台 Mini 固定用还是 Air/PC 浏览器都要看？要不要登录区分"我的库"？
2. **卡片一生**：粘贴新建 → 自动标题标签 → 复制使用 → 打星备注 → 改正文留版本 → 删废卡。新建、编辑、删除、查找、回顾一个不能少，删除必须单卡可删、有确认、有撤销。
3. **50/500 条时的查找**：关键词搜索（标题/正文/标签/调取码/备注）+ 标签点选 + 排序，缺一不可；要讲清 `@code` 这类直达是不是刚需。
4. **标签是治理不是字符串**：重命名自动改所有卡、层级、合并、移动防循环、删除不删卡并显示影响数、删除可撤销。
5. **保存语义**：什么算存了（失焦即存）、什么算版本（手动保存才建版，最多几版）、备注这类小字段要不要防抖、关窗切卡丢不丢稿。
6. **Agent 调取是不是 V1**：要不要给每条设短码让 AI 一句话调取？调取算不算一次使用计数？一台电脑一个钥匙、丢了能单独作废吗？
7. **云 vs 本机**：断网能不能看？换电脑要不要实时看到？两台同时改一条以谁为准（明确提示不静默覆盖）？备份怎么导？
8. **完成标准**：高频操作几步内完成；常用按钮一眼找到；手机小屏核心功能能用；空库/搜不到/断网/输错都有人话提示；数据刷新还在、另一台能看到才算存上。
9. **边界**：V1 必须有 vs 以后再说（多选组合筛选、标签上限放宽、模型自由输入、Key 脱敏展示等可以后排）。

## D. 从零开始的最佳完整提示词（可直接复制给全新 Planner）

> 以下整块可直接复制发给一个新的计划者 Agent。用的是普通用户语言，不需要懂技术。

---

今天我要正式从零开始开发一个「提示词管理工具」，请你先帮我把需求讨论清楚，不要一上来就写代码。

**我为什么要做它**

我平时用 GPT 这类大模型，写过很多好用的提示词，但都散在聊天记录、备忘录、Notion、本地 txt 里，想复用时找不到，复制粘贴还容易错。我想要一个自己的网页小仓库：把提示词粘贴进去存起来，以后好找、好改、好拿出来用，还能知道哪条最常用、效果最好。

**谁会用**

主要是我自己用。现在固定在一台 Mac Mini 上用浏览器打开，但我希望以后在另一台 Mac 或 PC 浏览器上登录同一个账号也能看到同一份库。暂时不需要多人协作，但我的数据不能被别人的账号看到。

**我最常见的使用故事**

故事 1（存）：我刚调好一条"翻译 + 意译"的提示词，粘贴到顶部输入框，它应该立刻变成一张卡片，标题和标签最好自动帮我想好（比如标题"中文翻英文并给意译"、标签"翻译"），我最多微调一下，不想每个字都自己填。如果 AI 实在想不出标签，宁可空着，也不要给我一个"无法分类"这种占位词。

故事 2（用）：第二天我要翻译，打开页面，在搜索框打"翻译"就找到它，点一下"复制"就粘贴到 GPT 里用，复制次数自动加 1。以后我按复制次数排序，就知道哪条最常用。

故事 3（养）：用了一阵发现这条写得不够好，我双击卡片进去改正文，改完按保存留一个版本，最多留 10 个版本，随时能回滚看 diff。标题、标签、备注、星级这种小改，点一下别处（失焦）就自动存了，不想再点一次保存。但正文只有我手动保存才算一个版本，不然切来切去版本就被撑爆了。备注是我自己写的"这条什么时候用、有什么坑"，和 AI 生成的东西分开。

故事 4（管）：半年后我有几百条了。我希望：搜关键词能跨标题、正文、标签、调取码、备注找到；点左侧某个标签只看这类；@加短码能直接跳到那条；排序能按最近更新、复制次数、评分切。标签要能重命名（所有带这个标签的卡自动跟着改）、能拖成父子层级、能合并重复、删除标签时告诉我会影响几条、删标签绝不能把卡片删了、删错了 10 秒内能撤销。废卡要能单独删（删前问我一次），不能只能清空整个库。

故事 5（Agent 调取）：我常用的几条想给 AI 直接用。给卡片设个短码（比如 jbyj，英文数字短横线，不超过 12 个字符），然后在 AI 里说一句"调取 jbyj"，它就按这条的角色直接开工，调取也算一次使用。每台电脑的钥匙分开，丢了一台只作废那一台的，不影响别的。

故事 6（不丢数据）：我在 Mini 上改完，刷新页面还在才算存上；以后在另一台电脑上改，3 秒左右这台自动看到，不用手动刷新。两台同时改同一条，不要悄悄覆盖，要明确告诉我"另一台刚改过，请刷新再改"。断网时至少能看本机缓存，恢复后自动重连并告诉我。关窗口、切换卡片时没存完的草稿不要丢。定期能一键导出 JSON/Markdown 备份，导入能整体恢复并告诉我哪些跳过了、为什么。

**V1 必须有（没有就不算可用）**

1. 粘贴正文建卡，AI 自动给标题（20 字内）+ 标签（1–3 个，短词，优先复用已有标签），失败可重试或直接建空白卡。
2. 卡片列表（标题、正文预览、标签、短码徽标、星级、复制次数）+ 详情/预览编辑 + 单卡删除（可配二次确认）+ 危险操作 10 秒撤销。
3. 复制按钮（复制成功才计数，失败要告诉我且不计数）+ 打星（点星和键盘 1–5 打、0 清除）。
4. 搜索 + 标签筛选 + 排序，三者可叠加；搜索刷新即清可以接受。
5. 标签树治理：创建、重命名自动改卡、移动防循环与重名、删除双模式且不删卡、影响数提示、撤销。
6. 保存语义：小字段失焦即存、正文手动才建版（10 版上限）、备注防抖不丢不串卡、关窗切卡先存草稿。
7. 版本历史 + 回滚（回滚不新增版本）+ 行级对比。
8. 导入导出 JSON/Markdown（含短码、版本、备注），非法导入不覆盖现有数据并说清原因。
9. 登录（邮箱链接 + Google 登录都行）+ 云端主存 + 多端实时同步 + 断网缓存 + 冲突明确提示。访问地址固定一个（比如 `http://192.168.31.60:3100`），不要让我在 localhost 和局域网地址之间猜。
10. 短码 + AI 调取：短码冲突实时红字，调取命中计数，钥匙每设备独立、可撤销。
11. 基础体验：手机小屏核心功能能操作（比如底部抽屉）、亮/暗主题、空库/搜不到/离线都有人话引导。

**以后再做（V1 不要膨胀）**

组合筛选（又含 A 又不含 B 这类）、标签上限从 3 放宽到 10、模型列表自由输入新模型、API Key 脱敏显示、旧同步链路退场、短码连字符规则收紧、掉登录监控 Kanban。这些现在提出来只是记下来，V1 先不做。

**完成标准（请按这些验收，不要用"界面好看"这种话）**

- 存一条：粘贴到建卡 1 步；标题标签自动来，我只微调。
- 用一条：搜索到复制 2 步内；复制次数实时 +1。
- 改一条：小字段失焦即有"已自动保存"；正文手动保存才多一个版本。
- 找一条：500 条时搜关键词或点标签 1 次定位，不用一条条翻。
- 删一条：有确认，误删 10 秒内能回来；删标签不删卡。
- 换端：A 端改完 B 端 3 秒左右自动看到；刷新都在；冲突有明确提示不覆盖。
- 故障：断网有横幅 + 重试；导入失败不丢库；刷新不丢草稿。

## E. 可提前避免的返工

1. **单卡删除**：PRD 写"不做删除"，产品报告即判 P0 缺口。Day 1 问一句"废卡怎么删"即可避免。
2. **搜索**：PRD 写"不做搜索"，30+ 卡即崩。Day 1 问"500 条时怎么找"即可暴露。
3. **同步假设**：localStorage → `store.json` + SSE → Supabase 三级跳，每次重写写入/冲突/MCP 假设。Day 1 讲清"以后要换电脑看、两台同时改怎么办"，至少把"单记录写入 + 版本号/条件更新 + 不整库覆盖"做成约束。
4. **标签用字符串数组**：重命名/层级/合并/校验全部返工。Day 1 讲"重命名标签要自动改所有卡"，Planner 自然会做 ID 解耦。
5. **保存 vs 版本**：失焦建版撑爆 10 条、关窗丢稿、备注串卡，全是语义没定义。Day 1 一句话"小改自动存、大改手动才留版"定终身。
6. **调取码与 MCP 后加**：字段、冲突、计数、令牌、RPC 全是侵入式。Day 1 讲故事 5，Schema 自然留位。
7. **HTTP IP 坑**：`crypto.randomUUID` / 剪贴板安全上下文、localhost 与 LAN 白名单、`.local` 代理劫持，Day 1 定死"只用一个精确访问地址 + 服务端生成秘密 + 复制失败有兜底"可省两轮真机返工。
8. **完成标准模糊**：Day 1 用"几步完成、刷新还在、另一端可见"代替"好看好用"，验收一次过。

## F. 无法完全避免的正常迭代

1. **看到真 UI 才知道的别扭**：标题被挤压让出顶行、高亮同色遮挡、胶囊盖住短码徽标、Composer Enter 与换行打架、逗号分隔标签反人类——必须点两下才有体感，归正常打磨。
2. **真机双端才暴露的并发**：connect 模式摇摆、写队列永久阻塞、掉登录后快照覆盖（BUG-12），仿真不如用户真实断网/令牌过期一次。Day 1 只能定原则（不静默覆盖、覆盖前备份、可重试），不能消灭。
3. **Agent 自然语言的改写**：连字符短码被改写致未命中，协议级全对、自然语言翻车——上线前想不到，归观察项正常收敛。
4. **模型与密钥生态漂移**：新模型两周即出、8 厂商回退与报错文案、安全披露强度，属持续运营，不是 Day 1 能冻住的。
5. **用户习惯分化**：自动粘贴建卡 vs 手动确认、标签上限 3 vs 10、退场旧链路 vs 长期保留——真实用了才有答案。2026-09-04 待办全取消本身就是"停止优化、保留现状"的正常决策。

## G. 最终结论

对以后启动类似项目，最值得保留的一条经验：

> **Day 1 不要讲功能点，要讲"卡片的一生 + 500 条时怎么找 + 两台同时改怎么办 + 删错了怎么回来"。**

本次复盘最大结论：该产品真正的分水岭不是 UI，而是"存储假设"——单机字符串标签库与云端多端可调取库是两种产品，Day 1 用六个使用故事把一生讲完，Planner 自然会选对存储、留对字段、定对保存与冲突语义；剩余的 UI 别扭与真机并发，留给迭代是正常的，不必自责。
