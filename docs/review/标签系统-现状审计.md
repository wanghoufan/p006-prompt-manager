## 三、存量标签去重统计（data/store.json 全量）

| 指标 | 数值 |
|---|---|
| 卡片总数 | 32 |
| tags 总条目数 | 56 |
| 去重后标签数 | 14 |
| 无标签卡片 | 1 |
| 含多级分隔符标签（拆分风险） | 0 |
| 长度 > 4 的标签 | 3（多agent编程 / token经济学 / 多aengt编程） |

去重后的 14 个标签：

```
无法分类(1)  开发恢复(11)  经验记录(5)  多age(3)   工程收尾(3)
代码检查(8)  界面测试(7)   qa基线(8)    多agent编程(5)  token经济学(1)
环境桥接(1)  vpn(1)       多aengt编程(1)  预览服务(1)
```

（括号内为使用频次）

**已确认的存量脏数据（迁移时必须处理）：**

1. **截断碎片标签**：`多age`（3 次）— 是 `多agent编程` 被 `normalizeTags` 的 `slice(0, 4)`（`cards.ts:107`）截断后的产物；AI 生成路径截断、手动路径（`parseTags`，`cards.ts:111-113`）不截断，**两套规则并存导致同一实体两种标签并存**。
2. **错别字重名**：`多agent编程`（5 次）与 `多aengt编程`（1 次）— 违反「同一父级下不允许逻辑重复标签」约束，迁移需合并。
3. **占位脏标签残留**：`无法分类`（1 次）— 属于 `DISCARD_TAGS`（`cards.ts:90`）应丢弃的占位标签，但因 `parseTags` 手动路径不过滤，存量残留。

> 结论：存量标签无多级路径拆分需求（0 个含分隔符标签），主要工作集中在「去重 + 脏数据合并」而非「路径拆树」。

## 六、下一步迁移建议（摘要，详细方案由【节奏】第 2 步展开）

1. **数据量小（32 卡 / 14 标签），推荐一次性迁移**，无需增量；先备份 `data/store.json`（沿用 `.bak` 先例）+ 导出 localStorage 副本。
2. **拆树需求为 0**（无含分隔符标签），迁移聚焦：① 14 个去重标签建 `tags` 实体（含稳定 id）；② 脏数据合并：`多age`→`多agent编程`、`多aengt编程`→`多agent编程`、`无法分类`→删除；③ 由 `Card.tags: string[]` 派生 `prompt_tags` 关联。
3. **存量 Card.tags 保留还是删除需决策**：保留可保兼容（旧客户端 `isCard` 仍通过），删除则更干净但需同步改 `isCard` 校验与所有读写路径——建议迁移方案中给出取舍。
4. **关系层建议放 `serverStore` 同层**（新增 tags/prompt_tags 集合进 `data/store.json`），沿用现有 writeChain 落盘 + SSE 同步机制，不引入数据库依赖。
5. 迁移脚本输出 dry-run 报告（合并前后标签对照）供验收，符合「无确认不执行大范围变更」约束。
