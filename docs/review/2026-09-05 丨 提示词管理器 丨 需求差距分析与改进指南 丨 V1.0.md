## 1. 项目背景（一句话 + 时间线）

**一句话：** 这是一个帮你"存提示词、用提示词"的个人小工具：把写给 AI 的话粘贴进来集中管，用的时候点一下复制出来，还能知道哪条最好用。

**时间线（真实发生的事）：**

| 时间 | 发生了什么 |
|---|---|
| 2026-08-15 | 第一版需求定稿（PRD v1）：定位是"本地网页、只存自己浏览器里、只接一个 AI 模型"，明确写了好几样"不做"（不同步、多设备、删卡片、搜正文都不做） |
| 2026-08-15 | 产品验收报告：功能都做出来了，但指出一个硬伤——**建错的卡片删不掉**，只能把整个仓库清空 |
| 2026-08-25 | v1.1 补上：单卡删除、跨设备同步、调取码、MCP（让 AI 软件直接调你的卡片） |
| 2026-08-27 ~ 08-28 | 标签体系大返工（P0 批次）：标签从"卡片上的一串字"升级成"有层级、可重命名、可移动、可合并、可组合筛选的树"，顺带补了搜索、批量管理、撤销、移动端抽屉等 |
| 2026-08-29 ~ 08-30 | AI 从"只认 DeepSeek"升级成"8 家厂商随便切" |
| 2026-09-01 ~ 09-03 | 最大的一次搬家：从"局域网小文件同步"搬到"Supabase 云端数据库"（登录、权限、实时同步、冲突保护、MCP 云端令牌），双设备真机验收通过，审核放行 |
| 2026-09-03 ~ 09-04 | BUG-12（一次真实的数据丢失事故）修复并部署；BUG-13（标签表漏了一个版本号字段）修复并发布；用户裁定剩余待办全部取消，项目进入"现状运行期"（平时就用，不再折腾） |

**核心一句话：** 最开始要的是"单机记事本"，最后长成了"带登录、多端同步、AI 软件可调用、跑在自家服务器上的云产品"。中间每一次"长大"，都对应一次当初没说清楚、后面返工补上的东西。

## 2. 当前产品已经发展成什么样（现状快照，2026-09-04）

给小白看的"现在这个软件会什么"：

- **存东西**：每张"卡片"存一条提示词，有标题、正文、标签、星级、复制次数、备注、调取码（短代号）、版本历史、思维方式总结。
- **找东西**：左边标签树（可分层、可拖、可搜），顶部搜索框（搜标题/正文/标签/备注，`@代号`直达），按复制次数/评分/时间排序，组合筛选（包含任一/必须同时有/排除）。
- **改东西**：点卡片进详情改，失焦自动存（像腾讯文档），正文手动保存才记一个版本（最多 10 个，可回滚、看改了哪几行），删卡有确认 + 10 秒内可撤销。
- **多端同步**：登录后（邮箱链接或 Google 登录），两台电脑 3 秒内互相看到对方的增删改；断网重连自动补；两边同时改同一张卡，后保存的人会收到明确冲突提示，不会悄悄覆盖。
- **AI 相关**：粘贴正文后 AI 自动起标题、打标签；可一键整理正文格式；可总结"这条提示词用了什么思维方式"；支持 8 家 AI 厂商切换。
- **MCP（给 AI 软件用的"调取接口"）**：每张卡可设一个短代号，在 AI 编程软件里说一句"调取某某"，AI 就把那条提示词当成新的工作指令；每台设备用独立令牌，可单独撤销。
- **跑在哪**：家里 Mac Mini 的 Docker 容器里，`http://192.168.31.60:3100` 打开就用；数据在云端数据库 + 本机缓存 + 定期备份三处。
- **规模**：云端 54 张卡（53 张真实 + 1 张保留测试卡），标签 20 多个，版本、关联近百条。

## 3. 最开始需求与当前产品的差距（10 个重要差距，每个回答 7 问）

> 写法说明：每个差距严格按"当时怎么说 / 现在什么样 / 差在哪一句话 / 为何提前想 / 不说会怎样（结合本项目）/ 下次普通人怎么说 / 好处"七问展开。

---

### 差距 1：卡片能不能单独删除

**（1）我最开始是怎么说的？**
PRD §9 原话大意："卡片删除与回收站，第一版默认不做删除"。需求文档里没有任何"删除一张卡"的按钮描述。

**（2）当前最终变成了什么？**
详情面板底部有"删除卡片"按钮（带确认，可选"以后不再确认"）；卡片悬停有删除小按钮；支持批量选中多张一起删；删除后 10 秒内可撤销；误删测试卡 12 张就是用这个能力批量清掉的。

**（3）中间到底差在哪里？**
一句话：**只想了"怎么存"，没想"存错了怎么办"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：粘贴时手抖多贴一次、AI 起了个"未命名提示词"的废卡，这些天天发生。产品报告里写得最直白：废卡"永久污染仓库"，想清理只能"清空我的仓库"把全部数据一起毁掉。本项目 8 月底的验收卡里就混进了好几张 `composer-*-qa` 测试废卡，当时只能留着不敢删。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：产品报告把"无法单独删除"列为头号易用性缺口（P0 补丁），v1.1 被迫返工补删除按钮；后来 P2-10 又补网格直删入口、P2-11 补批量删除、P2-5 补删除撤销。一次"不做"的决定，换来三轮补课。

**（6）下一次我应该怎么说？**
> "我粘错、建错是常事。每条记录都要能单独删，删之前问我一声，删完最好能反悔几秒钟。"

**（7）提前说清楚以后有什么好处？**
删除、撤销、确认框一次做到位，不用 v1 上线后被废卡恶心、再排三轮补丁；Agent 也不会把"清空全部"当成唯一的清理手段。

### 差距 2：数据多了以后怎么找（搜索）

**（1）我最开始是怎么说的？**
PRD 只给了"点标签筛选 + 按复制次数/评分排序"，§9 明确写"搜索正文内容"不做。默认世界里只有几十条、肉眼扫得过来。

**（2）当前最终变成了什么？**
顶部搜索框：搜标题/正文/标签/备注，大小写不敏感，`@代号`直达某张卡，匹配的字高亮显示，显示"命中 x / 共 y"，空结果有引导；搜索和标签筛选、排序叠加使用；还有按相关度排（标题命中排前面）。

**（3）中间到底差在哪里？**
一句话：**只想了"怎么分类"，没想"东西多了靠眼找不动"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：P2-2 的原话是"积累 30+ 卡片后想找翻译相关提示词，需逐标签点选或肉眼扫 3 列网格"。本项目 9 月初已经 54 张卡，没有搜索就是灾难。标签再整齐，也回答不了"我记得正文里有句话但忘了归哪类"。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：P2-2 单独立项补搜索（含高亮、@直达、相关度排序三连），SortBar、计数、空态全要跟著改。这属于"页面结构级"返工，比加个按钮贵得多。

**（6）下一次我应该怎么说？**
> "过几个月我会有几百条，我不想一条条翻。我想打几个字就找到，不管那几个字在标题、正文还是标签里。最好打个代号就能直达。"

**（7）提前说清楚以后有什么好处？**
搜索框的位置、高亮样式、排序规则第一天就留好，后面加标签体系时不用推倒重来；Agent 也不会把"筛选"当成唯一的查找手段。

### 差距 3：标签到底是什么（最大的一次返工）

**（1）我最开始是怎么说的？**
PRD §5.1："标签 2~4 个字、每张卡 1~3 个、AI 自由生成 + 优先复用已有"。标签只是"卡片上的一串字"，面板单选筛选，再点取消。

**（2）当前最终变成了什么？**
标签是独立的"树"：可建父子层级（如 SOP/每日）、可重命名（所有带这个标签的卡自动跟着改）、可拖拽移动（带防循环检查）、可合并重复标签、可批量移除、删除前显示"有 N 条提示词在用"、所有操作 10 秒可撤销、上限从 3 个放宽到 10 个、支持"包含任一/必须同时有/排除"组合筛选 + 含子标签开关。

**（3）中间到底差在哪里？**
一句话：**把"标签"当成了"备注"，其实它长大后是一套"分类系统"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：用户原话"标签重命名时，带这个标签的笔记应该自动修正过来"。还有截图抗议："不能用逗号分隔加多个标签"。审计发现存量 32 张卡就有截断碎片（`多age`）、错别字（`多aengt编程`）、占位脏标签（`无法分类`）——规则没提前定，脏数据第一天就开始攒。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了，而且是最贵的一次：8-27 审计确认"无独立标签实体、无层级、无补全"，8-28 一天内连做 P0-8（重命名）、P0-B（合并）、P0-C（组合筛选）、P0-9（交互重构）、P0-A（安全闭环）五个 P0，外加 22 项标签能力迁移和脏数据合并。这是全项目返工密度最高的一天。

**（6）下一次我应该怎么说？**
> "标签是我以后找东西的主要办法。我要能改名（改完所有卡自动跟着变）、能分大类小类、能合并重复的、删之前告诉我会影响几张卡、删错了能反悔。一次加好几个时不要让我打逗号。"

**（7）提前说清楚以后有什么好处？**
标签表、关联表、重命名联动第一天就设计好，不用从"字符串数组"推倒成"树 + 关联表"再写迁移脚本洗脏数据；"上限几个"这种产品决策也不用来回改（3→10）。

### 差距 4：数据存在哪、丢了怎么办（三次搬家 + 一次真丢）

**（1）我最开始是怎么说的？**
PRD §7："卡片数据存浏览器 localStorage"，还贴心注明"约 5MB 上限，卡多可迁 IndexedDB"。

**（2）当前最终变成了什么？**
三层：云端 Supabase 数据库是老大（6 张表、分人隔离），本机 localStorage 是缓存，家里服务器还有定期备份；写操作带版本号（revision），冲突拒绝；任何远端快照覆盖本机前先备份、可合并找回（BUG-12 的修复）。

**（3）中间到底差在哪里？**
一句话：**只想了"存得下"，没想"换电脑、清缓存、断网了怎么办"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：v1.1 先搬到"服务器小文件 + 局域网同步"，9 月再搬到"云端数据库"。BUG-12 是血的教训：用户在登录掉线但没察觉时编辑了一天，刷新后远端旧快照把本机编辑全覆盖，三处都没留底，**当天数据永久丢失**。PRD 那句"5MB 够用"在数据丢失面前毫无意义。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：同步架构换了三代（localStorage → serverStore/SSE → Supabase/Realtime），每次搬家都要导数据、做映射、验孤儿；BUG-12 之后又补了"覆盖前备份 + 本机独有合并"两道保命机制。这些是数据层返工，最贵、最险。

**（6）下一次我应该怎么说？**
> "我以后可能换电脑、清浏览器。数据不能只躺在一台机器的一个角落里。断网时我改的东西不能丢，刷新页面不能把我刚改的冲掉。"

**（7）提前说清楚以后有什么好处？**
第一天就定"云端为准 + 本机缓存 + 备份"，Agent 会直接上带版本号的写入，不会先做"整包覆盖"的简易同步再推倒；BUG-12 这类"静默丢数据"事故根本没机会发生。

### 差距 5：要不要多设备同步（一句"不做"变三个月主线）

**（1）我最开始是怎么说的？**
PRD §9 原话：数据同步/云存储/多设备，"明确不做"。

**（2）当前最终变成了什么？**
登录（邮箱链接 + Google）→ 云端实时同步（3 秒互推）→ 断线重连 → 并发冲突提示 → 每设备独立 MCP 令牌 → Docker 自托管。全项目 9 月的主线就是它，还过了正式审核放行。

**（3）中间到底差在哪里？**
一句话：**把"以后再说"的东西，默认当成了"永远不要"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：v1.1 用户就要"跨设备实时双向同步"了，8-28 又有"两端同时操作丢标签"的担忧，9 月直接全量上云。如果第一天就说"以后大概率要"，Agent 会把"整包覆盖"这种以后必死的方案排除掉，省掉 serverStore 整整一代。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：同步方案写了两套（SSE 整包 → Realtime 逐条），版本号机制上了两套（整库 version → 逐记录 revision），MCP 从"读本地文件"改成"调云端接口"。等于同步这条线做了两遍。

**（6）下一次我应该怎么说？**
> "第一版我一个人一台电脑用就行，但以后很可能两台电脑一起用。你先按单机做，但别用以后多设备必死的做法，给我留好升级的门。"

**（7）提前说清楚以后有什么好处？**
Agent 会避开"整包覆盖"深坑，数据结构里预留"归属人、版本号"字段；以后真上云，只是"接上"，不是"推倒"。

### 差距 6：调取码 + MCP（需求里一个字都没有的新大陆）

**（1）我最开始是怎么说的？**
PRD 全文没有任何"调取码""MCP""让别的软件调用"字样。当时的世界只有"人打开网页、点复制"。

**（2）当前最终变成了什么？**
每张卡一个短代号（`@sop`这种），MCP 服务 `prompt_manager_activate_prompt`：在 AI 编程软件里报代号，云端校验令牌后把正文作为新指令注入，复制计数 +1。令牌每设备独立、可撤销，撤销后那台立刻失灵、另一台不受影响（双设备隔离验收通过）。

**（3）中间到底差在哪里？**
一句话：**只想了"人用"，没想到"AI 也要用"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：用户真正高频的用法可能是"在写代码时让 AI 直接调一条 SOP 提示词"，而不是"打开网页复制粘贴"。这个用法一旦成立，代号规则（连字符会被 AI 改写，BUG 验收里真实踩坑）、令牌安全、私有代号唯一性全是新需求。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：v1.1 硬加 code 字段和 MCP 子包；云迁移时 MCP 又从"读本地文件"重写成"调云端接口"；还出过"旧版 MCP 进程赖着不走、改了也不生效"（10 个长驻旧进程）的运维坑。等于 MCP 这条线也做了两遍。

**（6）下一次我应该怎么说？**
> "以后我可能想在 AI 软件里一句话调出某条内容，每条给个简短好念的代号。你先帮我把代号留好，调用的事以后再说。"

**（7）提前说清楚以后有什么好处？**
代号字段、唯一性校验第一天就有，MCP 是"长出功能"而不是"打洞加塞"；连字符坑（`bug11-test2` 会被 AI 改写）也能在命名规则里提前避开。

### 差距 7：AI 模型写死一家（DeepSeek → 8 家）

**（1）我最开始是怎么说的？**
PRD §2/§6：模型 `deepseek-v4-flash`，密钥 `DEEPSEEK_API_KEY`，接口地址、鉴权方式全写死，连提示词模板都贴好了两段。

**（2）当前最终变成了什么？**
设置里 8 家厂商（DeepSeek、智谱、腾讯、豆包、Kimi、Google、OpenAI、OpenRouter）下拉切换，模型、地址、Key 都能改；思维总结模板用户可自定义。

**（3）中间到底差在哪里？**
一句话：**把"第一家试用的供应商"写成了"永远的供应商"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：8 月底模型列表就要大改（中国厂商模型全量更新、OpenCode 拆成 Go 版和免费版、请求超时、返回格式增强），一共 8 个提交全是换模型相关。写死一家，等于每次换模型都要改代码。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：8-29/30 两天连做"通用 AI 接口"（8 适配器 + 工厂 + 设置页四字段），还留下 4 个 P1（Key 明文同步、模型写死下拉、报错文案过时、保存心智割裂）慢慢还。产品 backlog 里 AI 相关的 P1 最多。

**（6）下一次我应该怎么说？**
> "先接一家能用就行，但以后我肯定想换别的试试。换模型、换地址、换钥匙的事让我在设置里自己点，别每次都改代码。"

**（7）提前说清楚以后有什么好处？**
第一天就是"适配器 + 设置页"结构，加一家厂商是"加一行配置"，不是"重写调用层"；密钥放哪、报错说什么也一次想好。

### 差距 8：改了东西怎么算"改完"（版本、自动保存、回滚语义）

**（1）我最开始是怎么说的？**
PRD §5.5："点保存 → 记一个版本，最多 10 个，回滚不记新版本"。听起来很清楚。

**（2）当前最终变成了什么？**
失焦自动存（不记版本）vs 手动保存/Ctrl+Enter（记版本）两条线；备注 700ms 防抖边输边存；切卡/关弹窗前自动收草稿；版本可看行级 diff；危险操作 10 秒撤销；云端写入带版本号、冲突明确提示。

**（3）中间到底差在哪里？**
一句话：**只想了"版本是什么"，没想"什么时候算一次修改"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：P2-1 原话"长文编辑频繁切焦，每次失焦都产生一版，数次操作即把有价值历史挤出"。CODE_REVIEW 也点名"失焦即建版极易撑满 10 条"。用户要的是"里程碑"，Agent 给的是"每次松开鼠标都记一笔"。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：P2-1 拆保存路径（`saveBodyOnly` vs `saveBodyWithVersion`），P1-2 补"关弹窗/切卡不丢稿"（两处组件 6 条路径），P2-4 补备注定时器清理，P2-5 补四类危险操作撤销。 "保存"这一个词，返工了四轮。

**（6）下一次我应该怎么说？**
> "我改东西时你帮我自动存着，别让我丢字。但'记一个版本'这种大事，必须我亲手按（或按快捷键）才算。关窗口、切换时别把我没写完的弄丢。"

**（7）提前说清楚以后有什么好处？**
"自动存"和"记版本"第一天就是两条线，版本历史干净可回滚；撤销、草稿收尾一次到位，不用四轮补。

### 差距 9：手机/小屏/好不好看（响应式 + 主题 + 面板）

**（1）我最开始是怎么说的？**
PRD §3：左侧标签、右侧卡片，样式"自选，不强制"。没有手机、没有窄屏、没有主题、没有面板宽度。

**（2）当前最终变成了什么？**
小屏下右侧面板变底部抽屉；面板可拖宽（320~720px，双击重置，宽度记住）；卡片 3 列 + 2~3 行正文预览；搜索高亮配色重做并过 WCAG 对比度；亮/暗/跟随系统三主题（含防闪烁）；标题被挤压都单独改了一版（9176c56）。

**（3）中间到底差在哪里？**
一句话：**只画了"大屏长的样子"，没说"小屏、晚上、眼睛累的时候什么样"。**

**（4）为什么这一点应该尽量提前想？**
真实场景：P2-3 原话"窄屏下编辑区不可见，只能靠双击进弹窗"。P0-F/P0-6/P0-7 全是"排版、预览、高亮、悬浮按钮"这种"看着用着别扭"的返工。好不好用，一半在这些地方。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：P0-F 面板排版、P0-6 高亮配色（还修了两次：同色遮挡 bug）、P0-7 悬浮胶囊、P2-3 移动抽屉、P0-5/P0-6 亮色主题、面板拖宽、正文优先布局……UI 微调贯穿 8 月整月，提交数占了近三分之一。

**（6）下一次我应该怎么说？**
> "我白天晚上都用，晚上要不刺眼。窗口拉窄、平板竖着时也要能改东西。字小、高亮看不清我会直接说。"

**（7）提前说清楚以后有什么好处？**
主题变量、高亮色、抽屉结构第一天就在，后面是"调参数"不是"改结构"；Agent 也不会把"能显示"当成"好用"。

### 差距 10：坏情况和"怎么算做完"（异常 + 验收标准）

**（1）我最开始是怎么说的？**
PRD 几乎没写坏情况：没网怎样、AI 挂了怎样、导入坏文件怎样、两边同时改怎样、第一次打开空仓库看什么，全没写。验收标准 = "功能有就行"。

**（2）当前最终变成了什么？**
空仓库有引导文案；离线/连接中/在线三态横幅；导入坏文件提示且不覆盖；AI 失败 toast + 重试/直接创建；复制失败不计数；云端冲突明确 toast；MCP 撤销负向验证；QA 清单 300+ 行回归项；双设备真机验收 + 隔离恢复演练全绿。

**（3）中间到底差在哪里？**
一句话：**只说了"顺的时候什么样"，没说"不顺的时候什么样、怎样算做完"。**

**（4）为什么这一点应该尽量提前想？**
真实场景全是坏情况教做人：BUG-9（HTTP 下令牌生成不了）、BUG-10（剪贴板被浏览器拒绝）、BUG-11（写队列被旧快照覆盖）、BUG-12（丢数据）、写队列停摆（请求挂死整队不动）、MCP 旧进程赖着不走。每一个都是"顺时没想到"的东西。

**（5）如果一开始没有说，会发生什么？**
本项目真实发生了：异常处理是返工重灾区——复制计数修了两轮（虚增→仅成功计数），空/离线文案修了两轮（P2-7→云端重试横幅），导入从"整体覆盖"补到"部分导入 + 跳过清单"，冲突从"最后写入覆盖"补到"版本号拒绝 + 提示"。没有验收标准，Agent 只能"看着像做完"就交。

**（6）下一次我应该怎么说？**
> "你每做完一个功能，都告诉我：没网时怎样、搞错时能不能反悔、坏文件进来会不会毁掉我的东西。第一次打开空空的时候，别给我看白板。"

**（7）提前说清楚以后有什么好处？**
"坏情况清单"就是验收标准，Agent 做完自己先对一遍；BUG-9/10 这类"换个浏览器就不行"的问题在开发时就被问出来，不用等真机验收 Bloomberg 式爆雷。

## 4. 主要返工来源（三类）

### A. 本来可以提前避免（第一天说清楚就能省）

1. **单卡删除**：PRD 写"不做"，产品报告当天就判 P0，三轮补（单删→直删→批量+撤销）。
2. **搜索**：PRD 写"不做"，30 张卡后必加，页面结构级返工。
3. **标签上限 3→10 + 逗号分隔交互**：产品决策 + 交互范式，P0-9 重构整个输入组件。
4. **AI 写死一家**：换模型即改代码，8-29/30 通用接口重写调用层。
5. **"整包覆盖"同步方案**：serverStore 整快照 → Supabase 逐条，同步线做两遍；BUG-12 是它的总爆发。
6. **失焦即建版**：版本语义，P2-1 拆线 + 四轮补保存。

### B. 正常产品迭代（不算失败，真用了才知道）

1. **标签树/合并/组合筛选**：标签从"备注"长成"分类系统"，只有数据量上来、重命名/合并的痛出现后，才知道要什么。审计→迁移→22 项能力，这个节奏是对的。
2. **调取码 + MCP**："AI 来调用"这个用法，是先有工具、后有需求，v1.1 长出来正常。
3. **面板拖宽、正文优先、移动抽屉、亮色主题**：好不好用必须上手摸，P0-F/P2-3 这类越用越明白。
4. **思维总结模板自定义、备注字段、版本 diff**：用了之后"想要更多"，健康的需求生长。
5. **连字符代号坑、MCP 旧进程坑**：真实环境才会暴露的细节，提前想不到不丢人。

### C. 计划者本来应该主动发现（不怪用户）

1. **空状态**：第一次打开空仓库看什么？PRD 没写，Planner 该问。后来补了引导文案（P3-3）。
2. **删除确认 + 撤销**：删东西问一声、给反悔，是行业常识，用户不说 Planner 也该给。拖到 P2-5 才补全。
3. **导入是覆盖还是合并**：载入示例把用户数据整包替换，只靠一个 confirm 兜底，Planner 该追问"覆盖前要不要备份"。BUG-12 就是"覆盖"这个动作的终极形态。
4. **localStorage 5MB 上限 + 清缓存即丢**："只存浏览器"的风险，Planner 该第一天就摆出来让用户选，而不是写句"以后可迁 IndexedDB"。
5. **并发冲突**：两端同时改一张卡会怎样？SSE 整包时代 Planner 没问，9 月云迁移才用 revision 补上，中间还搭进去 BUG-11/12。
6. **HTTP 下剪贴板/加密 API 不可用**：BUG-9/10 的根因（`crypto.randomUUID`、Clipboard API 要安全上下文），Planner/Builder 该在定"用 IP 访问"时就想到。
7. **tags 表漏 revision 字段（BUG-13）**：6 张表 5 张有版本号、1 张没有，评审该用清单逐表对出来，不该等用户保存报错才发现。

## 5. 哪些事到底该谁负责（三类责任划分）

### 第一类：普通用户自己应该提前想清楚（不懂编程也能说）

- 我为什么要做这个工具？（每天复制提示词太散、找不着）
- 我什么时候打开它？（写代码前？聊天时？手机上还是电脑上？）
- 一次完整使用是怎样的？（粘贴→自动起标题→以后搜索→复制）
- 我最常做的 3 件事是什么？（存、找、复制）
- 哪些操作绝对不能麻烦？（复制必须一键；粘错必须能删）
- 数据多了我怕什么？（几百条后找不到；换电脑丢失）
- 什么情况下我会生气？（刚改的丢了；删错找不回；断网白干）

### 第二类：我不知道很正常，但计划者应该主动问（含空状态类例子）

- 第一次打开、一条数据都没有时，你希望看到什么？（空状态）
- 存错、粘错、删错时，你希望有几秒反悔？（确认 + 撤销）
- 导入/载入东西时，是"加进来"还是"替换掉"？替换前要不要先备份？
- 标题、标签改了，关联的地方要不要跟着变？（重命名联动）
- 两台设备同时改同一条，以谁为准？要不要提醒你？（冲突）
- 没网、AI 挂了、文件坏了时，你希望看到什么？（异常）
- 标签要不要分大类小类？以后想合并重复的吗？（分类生长）
- 代号想起多长？要不要避开难打的符号？（命名规则）
- 白天晚上都用吗？小屏要改东西吗？（主题 + 响应式）

### 第三类：技术人员负责，我不需要操心（只说效果，不说做法）

- 数据库建几张表、字段叫什么（含 BUG-13 那种 revision 字段）
- 用什么同步机制（SSE 还是 Realtime）、什么叫"记录级写入"
- 组件怎么拆、状态放哪、目录怎么组织
- 令牌怎么生成（服务端随机数 + 哈希存）、权限怎么写（RLS、SECURITY DEFINER 取舍）
- 超时几秒、重试几次、退避间隔（写队列 30s 超时）
- 构建用 webpack 还是 turbopack、lint 规则、migration 文件名
- 我只需要说："两边 3 秒内互相看到，冲突时告诉我别悄悄覆盖，令牌能单独撤销。"

## 6. 编程小白需求表达框架（10 问，每问含为什么/不说会怎样/普通人模板）

### 第 1 问：我为什么要做它？（一句话目标）

- **为什么**：目标是所有取舍的标尺。不知道目标，Agent 只能按"通用软件"脑补。
- **不说会怎样**：本项目 PRD 目标"本地管理" vs 后来"云同步+MCP"，目标漂移带来两代同步架构。
- **普通人模板**：> "我每天要跟 AI 打交道几十次，提示词散在聊天记录里找不着。我要一个地方统一存，用时一键拿出来，知道哪条最好用。"

### 第 2 问：我什么时候打开它？在哪台设备上？

- **为什么**：决定单机还是同步、桌面还是移动优先。设备 = 数据架构。
- **不说会怎样**：本项目"本地网页"默认单机，结果 v1.1 就被迫上同步，架构换代。
- **普通人模板**：> "主要在我家小主机浏览器上用，偶尔笔记本也看。第一版一台能用就行，但以后两台要能互通，你别用以后必死的做法。"

### 第 3 问：一次完整使用过程是什么？（从打开到关掉）

- **为什么**：流程里藏着所有页面和按钮。只说功能点，流程断点没人管。
- **不说会怎样**：本项目"粘贴→建卡→AI 补标题"是流程，但"建错→删"没在流程里，删除漏到产品报告才爆。
- **普通人模板**：> "我复制一段话，粘到顶部框里，自动变成一张卡。以后我想找，打几个字或点标签，找到后点复制。粘错了我要能删，删错了最好能反悔。"

### 第 4 问：我要存什么？每条有哪些内容？

- **为什么**：这是数据的样子。漏一个字段，后面加就是迁移。
- **不说会怎样**：本项目 code（调取码）、notes（备注）全是后加的，每加一个，导入导出、搜索、同步全要跟。
- **普通人模板**：> "每条有：正文（最重要的）、标题、几个标签、几颗星、用了几次、一段备注、一个短代号。以后可能加，但先这些。"

### 第 5 问：数据多了以后我怎么找？（几百条时）

- **为什么**：10 条和 500 条是两种软件。查找是最高频操作。
- **不说会怎样**：本项目无搜索撑到 30+ 卡，P2-2 结构级返工；标签也从字符串推倒成树。
- **普通人模板**：> "过几个月会有几百条，我不想一条条翻。打几个字就能找，不管在标题正文还是标签里。标签能分大类小类，能改名合并。"

### 第 6 问：哪些事我每天都做？哪些绝对不能麻烦？

- **为什么**：高频操作决定交互优先级。Agent 默认所有按钮平等。
- **不说会怎样**：本项目复制必须一键、粘贴即建卡、Enter 建卡，这些都是高频，Composer 重构专门伺候它们。
- **普通人模板**：> "我每天就是粘、找、复制。复制必须点一下就行。存错删错是常事，删要方便、能反悔。"

### 第 7 问：改错、删错、断网、清空时会怎样？（坏情况）

- **为什么**：顺境人人会做，坏情况才分高下。这是验收标准本人。
- **不说会怎样**：本项目 BUG-12 丢数据、复制虚增、导入覆盖，全是坏情况没提前说。
- **普通人模板**：> "我手抖是常事：粘错、删错、导错文件都可能。任何毁东西的操作前问我一声，毁完给我几秒反悔。断网时改的不能丢，刷新不能冲掉我刚写的。"

### 第 8 问：AI 在里面扮演什么角色？以后会换吗？

- **为什么**：AI 供应商换得比衣服还快，写死即返工。
- **不说会怎样**：本项目 DeepSeek 写死，8 月底 8 个提交全是换模型，通用接口重写。
- **普通人模板**：> "先接一家能用就行，自动起标题打标签。但以后我想换别的试试，换模型换钥匙让我在设置里点，别改代码。"

### 第 9 问：以后还想让谁用它？（人还是 AI 软件）

- **为什么**：人用 vs AI 调用，是两种入口。代号、接口、安全全跟着变。
- **不说会怎样**：本项目 MCP（AI 调用）是 v1.1 硬加的，云迁移又重写一遍，还有连字符坑。
- **普通人模板**：> "现在我就自己点着用。以后可能想在 AI 写代码时一句话调出某条，每条先留个简短好念的代号，调用以后再说。"

### 第 10 问：什么样算"做完了"？（我的验收动作）

- **为什么**：没有验收标准，"像做完"就是做完，坏情况全漏。
- **不说会怎样**：本项目前期验收靠"按钮都有效"，BUG-9/10/11 全是真机才爆。
- **普通人模板**：> "你每做完一个功能，我要能：正常走一遍、故意搞错一次（删错、导坏文件、断网）、换个浏览器试一次。三种都过才算完。"

## 7. 用户 / 计划者 / 开发 Agent 职责边界

| 事项 | 谁负责 | 说明 |
|---|---|---|
| 为什么做、什么时候用、最常做3件事 | **我（用户）说清楚** | 不懂编程也能说，是目标标尺 |
| 完整使用流程、存什么内容、怎么找 | **我（用户）说清楚** | 用普通人话讲故事就行 |
| 哪些不能麻烦、坏了会生气 | **我（用户）说清楚** | 这是验收标准本人 |
| 空状态、确认、撤销、覆盖还是合并 | **计划者主动追问** | 小白不知道这些词，但 planner 必须问（本项目 5 个 C 类返工全是没问） |
| 并发冲突、离线、异常、换设备 | **计划者主动追问** | 技术风险翻译成选择题让用户选 |
| 数据结构、同步机制、组件拆分 | **开发 Agent 自己定** | 用户只说效果（3 秒互通、冲突提醒） |
| 令牌、权限、超时重试、构建 | **开发 Agent 自己定** | 用户只说"能单独撤销""别丢数据" |
| 计划者该提醒什么 | **计划者主动提醒** | 换电脑风险、整包覆盖风险、HTTP 下 API 限制、代号命名坑 |
| 做完怎么验 | **三方共担** | 用户给验收动作（第 10 问），planner 写成清单，builder 自测后再交 QA |

**一句话判断法**：凡是"不懂编程也能感受到"的事（目标、流程、麻烦、生气）归我；凡是"我不知道这个词但天天会遇到"的事（空状态、撤销、冲突、离线）归计划者追问；凡是"我只关心效果不关心做法"的事（建表、API、组件、权限）归开发。

## 9. 三个最终结论

### 结论 1：这次返工最主要的 4 个原因

1. **把"以后再说"当成"永远不要"**：同步、多设备、删除、搜索，PRD 里四个"不做"，后来全做了，且同步线做了两遍。这是总根因。
2. **把"标签"想小了**：当备注写进去，当系统用起来。一天五个 P0，是全项目最贵的学费，对应审计里"无独立实体、无层级、无补全"的三无开局。
3. **"保存"只有一个词，没有两条线**：自动存 vs 记版本混在一起，版本被噪音撑满、草稿丢、备注串，拆了四轮。
4. **坏情况和验收标准缺席**：复制虚增、导入覆盖、并发覆盖、HTTP 限制、丢数据事故，全是"顺时没想到"。BUG-12 是这一条的纪念碑。

### 结论 2：如果只能改一个习惯，改这个

> **以后描述任何功能，都加一句"搞错了怎么办"。**

为什么是它：本项目最痛的三件事——删不掉（存错怎么办）、BUG-12 丢数据（刷新覆盖怎么办）、导入覆盖（导错怎么办）——全是这句话能提前抓出来的。它不需要任何术语，粘错、删错、导错、断网、刷新，人人听得懂。一句话，覆盖删除、撤销、确认、备份、合并、冲突六个返工大户，性价比全场最高。

### 结论 3：想法很模糊时，先让计划者完成这个再开发

> **先让计划者输出"一次完整使用过程 + 坏情况清单"，你点头后才写代码。**

具体是两样东西：一是"你打开软件第一秒到关掉，每一步点什么、看到什么"（含第一次空仓库）；二是"列出 5~8 个坏情况：存错、删错、导错、断网、两边同时改、换电脑，每个写一句话会怎样"。这两样齐了，页面、数据、异常、验收全有了。本项目如果 8-15 就有这两张纸，删除、搜索、撤销、冲突、备份五个坑至少能填三个。
