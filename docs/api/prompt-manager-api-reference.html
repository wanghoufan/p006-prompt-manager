Prompt Manager MCP · 接口参考

提示词管理器对外暴露两类接口：基于 HTTP 的共享数据同步与 AI 能力接口（Next.js Route Handler），以及基于 stdio 的 MCP 工具 prompt_manager_activate_prompt。本文为两者的完整契约说明。

协议 MCP 1.x / HTTP 1.1 编码 UTF-8 格式 application/json 存储 data/store.json

00一键接入

你不需要读完这份文档。把下面第一块里的话复制给你的 AI，剩下的它来做——装依赖、构建、找客户端、写配置、验证，全在这一条命令里。

请执行 node "/<项目根>/mcp/prompt-server/setup.mjs" 完成提示词管理器接入，成功后用一句话告诉我怎么用。
node "/<项目根>/mcp/prompt-server/setup.mjs"
✓

脚本会自动完成：装依赖 → 构建 → 探测本机装了哪些 AI 客户端并逐个写好配置 → 真调一次验证。

它只读你的提示词库，不会改动任何卡片、标签或调取码；连验证时本会发生的「复制次数 +1」也被特意指向了不可达端口，不留痕迹。改动配置文件前会自动备份为 <文件>.bak-<时间戳>。

01概述

所有接口围绕同一份服务端权威数据 data/store.json 工作：HTTP 接口负责读写与实时广播，MCP 工具负责按「调取码」把卡片正文交给模型执行。

🌐 HTTP 同步层

4 个端点。整份快照读写 + SSE 版本号广播，多端访问同一进程即天然共享，采用乐观并发控制（baseVersion）。

🤖 HTTP AI 层

3 个端点。服务端代理 DeepSeek，密钥不出服务端；覆盖标题标签生成、正文格式整理、思考摘要。

🔌 MCP 工具层

1 个工具。stdio JSON-RPC，供 WorkBuddy 等 MCP 客户端按调取码注入角色 / 任务指令，命中后自动计数。

🔗 工具端点

1 个端点。抓取外部链接标题（含微信公众号特殊降级策略），超时 8 秒。

03认证与配置

⚠

HTTP 接口当前不含任何鉴权。服务端假定运行在受信任的本机 / 局域网环境。若要暴露到公网，必须在反向代理层补充鉴权与访问控制。

MCP Server 以本地子进程 stdio 方式运行，同样不校验调用方身份，其安全性等价于本机用户权限。

配置项位置默认值说明
DEEPSEEK_API_KEY必填 · AI .env.local — AI 系列端点的上游密钥，仅存在于服务端进程，不下发到浏览器。缺失时 AI 端点返回上游未配置错误。
DEEPSEEK_BASE_URL可选 .env.local https://api.deepseek.com 上游网关地址，末尾斜杠会被自动裁剪。
DEEPSEEK_MODEL可选 .env.local deepseek-v4-flash AI 三个端点共用的模型标识。
PROMPT_MANAGER_API_URL可选 MCP 进程环境变量 http://localhost:3100 MCP 回写复制计数的目标地址。服务换端口时必须同步修改，否则计数静默失败。
allowedDevOrigins可选 next.config.ts 局域网主机名 / IP 放行局域网来源，否则另一台设备的同步请求会被当作跨域拦截。

04通用约定

  • 请求编码：所有带请求体的端点使用 Content-Type: application/json; charset=utf-8。
  • 响应格式：成功返回业务对象；失败统一返回 {"error": "中文可读消息"}，不含机器可读错误码字段，请以「HTTP 状态 + error 原文」组合判定。
  • 时间格式：全部为 ISO 8601 UTC 字符串，例如 2026-08-28T15:44:19.375Z。
  • 调取码匹配：大小写不敏感，比较前统一 trim().toLowerCase()。
  • 版本号语义：version 为单调递增整数。内容无变化时不递增、不落盘、不广播。
  • 缓存：所有响应均未设置缓存头，建议在客户端使用 cache: 'no-store' 读取快照。
  • 幂等性：POST /api/sync 内容一致时幂等（不产生新版本）；POST /api/sync/increment-copy 每次调用必然 +1，非幂等。
  • 方法限制：端点未实现的 HTTP 方法统一返回 405，响应体为空（0 字节、无 Content-Type）。已实测：DELETE /api/sync、GET /api/sync/increment-copy、GET /api/ai/format-body、POST /api/sync/stream 均为 405。

06端点

GET /api/sync

读取共享快照

返回服务端进程内存中的完整快照。数据文件缺失或损坏时不会报错，而是回退为空快照（cards: []、version: 1）。

请求参数

无请求参数，无请求体。

状态码

状态含义响应体
200成功返回快照{ cards, settings, tags, promptTags, version }
500进程级异常（极罕见）Next.js 默认错误页。文件读取失败已被内部兜底，不会透出。
405非 GET 方法空响应体（0 字节）
POST /api/sync

覆盖写入共享快照

把整份 cards / settings / tags / promptTags 推送到服务端，服务端为唯一事实来源。写入前会做两类校验：标签图合法性校验与基于 baseVersion 的乐观并发校验。

请求参数

参数类型说明
cards必填 Card[] 全量卡片数组。非数组直接返回 400。请传完整快照而非增量。
settings可选 Settings | null 应用设置。缺省或 null 时以 null 覆盖。
tags可选 Tag[] 标签树。非数组时忽略本次修改，保留服务端原值。非法结构会被过滤。
promptTags可选 PromptTag[] 关联关系。非数组时忽略。悬空 / 重复项会被过滤器剔除。
baseVersion可选 number 乐观并发控制：声明本次写入基于的服务端版本号。若服务端版本已变化则拒绝写入。省略则不校验。
i

服务端写入前 6 项强制校验（按代码执行顺序，命中即返回）。任一项不通过，整份快照拒绝落盘：

#校验error 原文（前缀均为「数据校验失败：」）
①同父级无重名同一父级下存在重名标签「{name}」
②标签 id 唯一标签 id 重复
③父标签存在标签「{name}」的父标签不存在
④层级无环标签层级存在循环
⑤关联不悬空标签关联指向不存在的标签 / 标签关联指向不存在的提示词
⑥关联唯一(prompt_id, tag_id) 关联重复

注：重名判定以 parent_id + name 为键，不同父级下允许同名；循环检测会沿 parent_id 链上溯，自环（parent_id === id）同样被拒。

内容无变化时：版本号不变、不落盘、不广播，用于阻断「远程回写 → SSE 回声 → 再回写」的推送死循环。

!

已知行为（务必按此实现客户端）：校验失败与版本冲突时，HTTP 状态仍为 200，ok 恒为 true，真正的拒绝信息以错误对象的形式透传在 version 字段内。

判定逻辑：typeof version === 'number' → 成功并更新本地已知版本；否则读 version.error 与 version.conflict。冲突时应重新 GET /api/sync 拉取权威数据后重试。

!

实测确认的高危行为：省略 settings 会把它清空。该字段走 b.settings ?? null，缺省或被显式传 null 时，服务端会把整个 settings 置为 null 并立即落盘（版本号照常递增）。

正确做法：任何时候都先 GET /api/sync 拿到完整快照，再原样回传四个集合，只改需要改的部分。tags / promptTags 若传了非数组值则被忽略、保留服务端原值，但 settings 没有这层保护。

状态码

状态含义响应体
200写入成功{ ok: true, version: number }
200被拒绝（校验失败 / 版本冲突）{ ok: true, version: { ok:false, error, conflict? } }
400请求体不是合法 JSON{ error: "请求体不是合法 JSON" }
400缺少 cards 或类型错误{ error: "cards 必须是数组" }
405非 POST 方法空响应体（0 字节）
SSE GET /api/sync/stream

订阅实时变更（Server-Sent Events）

长连接推送。连接建立后立即发送一次当前版本号，此后每次服务端数据变更广播新的版本号。客户端收到事件后应重新调用 GET /api/sync 拉取最新数据——事件本身只携带版本号，不携带数据。

请求参数

无请求参数。仅支持 GET。

响应头值作用
Content-Typetext/event-stream; charset=utf-8声明 SSE 流。
Cache-Controlno-cache, no-transform禁止中间层缓存与压缩转换。
Connectionkeep-alive保持长连接。
X-Accel-Bufferingno关闭 Nginx 代理缓冲，保证实时性。
i

心跳：每 25 秒发送一行注释帧 : ping，用于防止代理 / 浏览器断开空闲连接，客户端应忽略注释帧。

断线重连：浏览器 EventSource 会自动重连；客户端断开时服务端通过 abort 信号清理定时器和订阅，不会泄漏。

回声过滤：自己刚推送产生的版本号会同样广播回来。客户端需记录 lastPushedVersion 并忽略相等的版本号，否则会形成推送死循环。

状态码

状态含义响应体
200流已建立持续输出 data: {"version":N} 帧与 : ping 心跳
405非 GET 方法空响应体（0 字节）
POST /api/sync/increment-copy

调取计数 +1

按调取码给卡片的 copyCount 加一，与手动复制共用同一计数。MCP Server 命中卡片后会自动回调本端点；也可供外部脚本直接调用。写入成功后会递增版本号并广播 SSE。

请求参数

参数类型说明
code必填 string 卡片调取码。比较前执行 trim().toLowerCase()，因此大小写不敏感。空白串视为缺失。

状态码

状态含义响应体
200计数已递增{ code, copyCount }
400缺少或无效的 code{ error: "缺少 code 参数" }
404调取码未命中任何卡片{ error: "未找到调取码为 … 的卡片" }
500请求体 JSON 解析失败（空 body / 语法错误）{ error: "Expected property name or '}' in JSON at position 1…" } —— 引擎原生英文文案
500其它未捕获异常{ error: "服务器错误" }
405非 POST 方法空响应体（0 字节）

非幂等：每次成功调用都必然使计数 +1。请勿在重试逻辑中无保护地重复调用。

参数校验为非 strict：请求体里的多余字段会被静默忽略（已实测）。这与 MCP 工具 prompt_manager_activate_prompt 的 strict schema 形成对比——后者遇到未知字段会直接报 -32602。

POST /api/ai/generate-meta

AI 生成标题与标签

根据提示词正文生成不超过 20 字符的标题与一组标签。可传入已有标签作为候选，模型会优先复用。标签结果会经过归一化过滤（剔除脏标签），可能返回空数组。

⚠

实测确认：返回的 tags 可能少于、甚至完全不包含你传入的候选标签。实例：传 existingTags: ["代码检查","重构"]，返回 ["代码检查"]——「重构」被丢弃，且 tags 的数量、顺序、内容都不保证。

因此 tags 应视为「模型建议」，落库前需自行合并去重，不要直接当作最终标签集合覆盖原值。

请求参数

参数类型说明
body必填 string 提示词正文。前后空白会被 trim；trim 后为空串返回 400。
existingTags可选 string[] 已有标签列表，作为复用候选。非数组项会被过滤；缺省为空数组。

状态码

状态含义响应体
200生成成功{ title, tags }，两者可能为空串 / 空数组
400JSON 解析失败{ error: "请求格式错误" }
400正文缺失或为空白{ error: "正文不能为空" }
503未配置上游密钥{ error: "AI 服务尚未配置，请在 .env.local 中设置 DEEPSEEK_API_KEY 后重启服务" }
502上游错误 / 返回内容无法解析{ error: "DeepSeek 接口返回错误（…）：…" } 等
405非 POST 方法空响应体（0 字节）
POST /api/ai/format-body

AI 正文格式整理

保留正文语义与 Markdown 结构，仅清理粘贴造成的多余缩进、尾随空白与连续空行。模型温度固定为 0，输出上限 3000 tokens。不会为了模拟对齐而在行首补空格——对齐由阅读器渲染控制。

请求参数

参数类型说明
body必填 string 待整理正文。最大 50000 字符，超出返回 400。
alignment可选 "left" | "center" | "right" 对齐方式，仅影响提示词语气。非这三个枚举值时静默回退为 "left"，不报错。
!

实测确认：长正文会被静默截断。虽然入参上限是 50000 字符，但上游输出被限制为 max_tokens: 3000。实测传入 400 行 / 9091 字符，只返回了 227 行 / 5116 字符——后半段正文直接丢失，且接口仍返回 200，不会有任何错误提示。

建议：正文超过约 2000 汉字时自行分片处理，或对返回结果做长度校验（输出明显短于输入即视为截断）。

状态码

状态含义响应体
200整理成功{ body }，已 trim
400JSON 解析失败{ error: "请求格式错误" }
400正文缺失或为空白{ error: "正文不能为空" }
400正文超过 50000 字符{ error: "正文不能超过 50000 个字符" }
502上游错误或返回为空{ error: "DeepSeek …" } 或 { error: "AI 调用失败" }
405非 POST 方法空响应体（0 字节）
POST /api/ai/summarize-thinking

AI 思考摘要

为提示词正文生成一段思考摘要，输出上限 600 tokens。可传入自定义模板覆盖内置提示词。

请求参数

参数类型说明
body必填 string 提示词正文。trim 后为空串返回 400。
prompt可选 string 自定义模板。若包含 {body} 占位符则直接替换；不包含时会在模板末尾自动追加「提示词正文：\n{body}」。空白串视为未传。

状态码

状态含义响应体
200摘要生成成功{ summary }，已 trim
400JSON 解析失败{ error: "请求格式错误" }
400正文缺失或为空白{ error: "正文不能为空" }
502上游错误或返回为空{ error: "DeepSeek …" } 或 { error: "AI 调用失败" }
405非 POST 方法空响应体（0 字节）
⚠

状态码不一致（已知）：本端点与 /api/ai/format-body 把上游错误统一映射为 502，包括「AI 服务尚未配置」这类语义上应为 503 的场景。只有 /api/ai/generate-meta 会透出 503。请以 error 文案而非状态码区分「未配置」与「上游故障」。

GET /api/fetch-title

抓取网页标题

服务端抓取目标页面并提取标题，用于把链接转成 Markdown 卡片。提取顺序：<title> → og:title → 页面脚本中的 msg_title；微信公众号文章优先取 msg_title（其 <title> 常为空）。整体超时 8 秒。

TOOL prompt_manager_activate_prompt

激活提示词卡片（MCP）

通过 stdio 上的 JSON-RPC 2.0 调用。按调取码读取卡片，把正文包装成仅供模型执行的指令封套返回，同时异步回调 POST /api/sync/increment-copy 计数。传输层为 stdio，不适用 curl，但可用管道模拟一次完整会话。

接入配置

正常情况下这一节不需要看——一键接入 会自动完成下面的全部步骤。这里保留给需要手工核对或脚本跑不通的场景。手工配置时，在 MCP 客户端配置中注册一个本地 stdio server。注意配置文件路径不带点——带点的 .mcp.json 是 connector-proxy 专用，两者不要混用。

{
  "mcpServers": {
    "prompt-manager": {
      "command": "node",
      "args": [
        "/<项目根>/mcp/prompt-server/dist/index.js"
      ],
      "env": {
        "PROMPT_MANAGER_API_URL": "http://localhost:3100"
      },
      "description": "本地提示词管理库：通过调取码（code）加载角色或任务指令"
    }
  }
}
  • 构建：cd mcp/prompt-server && npm install && npm run build，产出 dist/index.js。建议把 command 写成 node 的绝对路径——MCP 客户端启动时常常没有 nvm / 用户 shell 的 PATH，只写 node 会报「找不到命令」。
  • 运行时要求：Node.js ≥ 18（ESM + stdio）。
  • 信任与生效：在客户端的连接器管理页保存后需点击「信任」，并新开会话才会加载新工具。
  • 触发方式：在对话中输入「调取 / 激活 / 加载 / 切换到 + 短码」，例如 调取 jnjp。
  • 数据源前提：只需要 data/store.json 这个文件存在（跑过一次 dev 服务并打开过页面即可），不要求 dev 服务此刻正在运行——工具是直接读文件的。文件不存在时返回「读取提示词库失败」。dev 服务只在「复制次数 +1」这一步被用到，且失败会静默跳过（可用 PROMPT_MANAGER_API_URL 覆盖地址）。

08限流与配额

!

当前版本未实现任何网关层限流。服务端不返回 X-RateLimit-* 头，也不会返回 429。以下约束来自实现本身的物理限制，集成时请按此估算容量。

维度约束说明
写入并发 串行队列 落盘通过 Promise 链串行化，同一时刻只有一个写操作在写文件。高频写入会排队，不会并发写坏文件，但吞吐受磁盘 IO 限制。
写入失败处理 静默日志 落盘失败只在服务端打印 [serverStore] 写入失败，不会向客户端返回错误，内存中的状态仍会被视为已更新。需要监控时必须自行采集服务日志。
上游抓取超时 8 秒 仅 /api/fetch-title 设置了 AbortController 超时；超时按 502 降级处理。
AI 调用超时 未设置 AI 三个端点未设置显式超时，依赖运行时默认网络超时。慢响应会长期占用连接，建议客户端自行设置 30 秒超时。
AI 上游配额 取决于 DeepSeek 账户 每个 AI 请求对应一次上游 /chat/completions。温度：格式整理固定 0，其余 0.5。输出上限即「静默截断阈值」：摘要 600 tokens，格式整理 3000 tokens——后者实测会在 200 响应中丢掉长正文的后半段，详见该端点的警告。
SSE 连接 无上限 订阅者数量不做限制（事件发射器已设为无上限监听）。每个连接维持一个 25 秒心跳定时器；客户端应主动关闭不再需要的连接。
请求体大小 未显式限制 除 format-body 的 50000 字符外，其余端点未设上限。整份快照写入受部署平台 body 限制约束。

生产环境建议

  • 加鉴权：在反向代理层强制鉴权，切勿裸奔到公网。所有端点当前均无身份校验。
  • 加限流：对 /api/ai/* 与 /api/fetch-title 这两个会外访的端点优先限流，防止被当作代理滥用。
  • 加超时：为 AI 端点在代理层设置 30 秒超时，并在服务端补 AbortController。
  • 重试策略：仅对 502 类上游故障做指数退避重试；400 / 404 / 422 属于确定性失败，重试无意义；increment-copy 非幂等，重试会导致重复计数。
