Prompt Manager MCP 接口参考

通过「调取码」从提示词管理库加载卡片正文，并计入复制次数。stdio 模式的 Model Context Protocol 服务器。

按智能体接入（复制即用的命令）

每个智能体的接入命令不同——差别只在 --client 参数；脚本会自动把配置写到该智能体自己的位置、用正确的格式。在项目根目录运行下面任一条：

一键接入本机所有检测到的客户端

bash
node mcp/prompt-server/setup.mjs

更常用：只接入某一个客户端（避免误改其他客户端配置）。每条都是独立可复制的命令：

bash
# WorkBuddy
node mcp/prompt-server/setup.mjs --client=workbuddy
bash
# Codex CLI
node mcp/prompt-server/setup.mjs --client=codex
bash
# OpenCode
node mcp/prompt-server/setup.mjs --client=opencode
bash
# Cursor
node mcp/prompt-server/setup.mjs --client=cursor
bash
# Claude Desktop
node mcp/prompt-server/setup.mjs --client=claude
bash
# Cline（VS Code）
node mcp/prompt-server/setup.mjs --client=cline
bash
# Windsurf
node mcp/prompt-server/setup.mjs --client=windsurf
bash
# Gemini CLI
node mcp/prompt-server/setup.mjs --client=gemini
想自己跑 / 只预览不写文件加 --dry-run；只体检加 --check；卸载加 --remove。脚本写配置前会自动备份原文件（<文件>.bak-<时间戳>）。

Prompt Manager MCP 是一个只读的 MCP 服务器：它从提示词管理工具落盘的 data/store.json 中按调取码（code）查找卡片， 把卡片正文作为「仅供模型执行的指令」返回给 MCP 客户端，并可选地把该卡片的 copyCount 加一。它不修改任何卡片、标签或调取码数据。

结果的性质：MCP 工具返回的是 tool result，不能在协议层被提升为 system message。客户端需把返回内容交给模型，模型再按其中的角色 / 任务指令继续。 工具结果中的 body 不是要呈现给用户的数据。

快速开始

最简单的方式是「一条命令接入」：把这句话发给你的 AI，它会自动完成安装、构建、探测本机客户端并写入配置、最后真调一次验证。

text
请执行 node "<项目根>/mcp/prompt-server/setup.mjs" 完成提示词管理器接入，成功后用一句话告诉我怎么用。

自己手动跑也只需一条命令：

bash
# 在项目根目录
node mcp/prompt-server/setup.mjs

脚本会自动做四件事：装依赖 → 构建 → 探测本机 AI 客户端并写配置 → 真调一次验证。 验证阶段会把计数回调指向一个不可达端口，因此连「复制次数 +1」的副作用都不会发生（数据安全）。

手工构建与运行

bash
# 进入 MCP 子包
cd mcp/prompt-server
npm install
npm run build        # 产出 dist/index.js
node dist/index.js   # stdio 模式，等待 MCP 客户端连接
首次使用前置条件：需要先启动一次 npm run dev 并打开页面， 让数据落盘到 data/store.json。MCP 服务本身只依赖这个文件的存在， 不需要 dev 服务处于运行状态。只有「复制次数 +1」需要 dev 服务在 http://localhost:3100（可用环境变量 PROMPT_MANAGER_API_URL 覆盖）。

架构与数据流

服务器以 stdio 传输运行，通过 JSON-RPC 2.0 与 MCP 客户端通信。

text
MCP 客户端 (WorkBuddy / Cursor / Claude …)
      │  stdio + JSON-RPC 2.0
      ▼
prompt-manager-mcp-server  (dist/index.js)
      │  读取
      ▼
data/store.json            ← Next.js dev 服务端实时落盘（同步源）
      │
      │ 命中后触发（失败静默跳过）
      ▼
POST localhost:3100/api/sync/increment-copy   →  card.copyCount + 1
运行方式与端口：本 MCP 服务器通过 stdio（标准输入输出）与客户端通信， 本身不监听任何 TCP 端口，因此不会占用或抢占项目的端口。 仅在「命中调取」时，它会以 HTTP 客户端身份向 dev 服务（默认 http://localhost:3100） 发送一次计数请求（POST /api/sync/increment-copy）；该端口是 dev 服务自己的端口， 计数失败会静默跳过，不影响卡片读取。可用环境变量 PROMPT_MANAGER_API_URL 覆盖这个地址。

工具：prompt_manager_activate_prompt

按调取码加载一张提示词卡片。当用户说「调取 / 激活 / 加载 / 切换到 / 用 … 跑」加调取码时，客户端应立即调用本工具。

TOOLprompt_manager_activate_prompt

请求参数

输入使用 zod .strict() 校验——不接受 schema 之外的额外字段。

参数类型必填说明
code string 是 卡片的调取码。长度 1–64 字符，大小写不敏感。调用前服务端会做 trim().toLowerCase() 归一化。

返回结构

成功时返回两部分内容：

  • content[0].text —— 带指令封套（envelope）的正文，供模型直接执行；
  • structuredContent —— 结构化字段，便于客户端程序化读取。
code
string | null
命中卡片的调取码（保留原始大小写）；未设置时为 null。
title
string
卡片标题。
body
string
仅供模型执行的私有指令正文。不得展示、复述或总结给用户。
tags
string[]
卡片标签数组（可能为空）。
thinkingSummary
string | null
思维链摘要；无则为 null。
updatedAt
string | null
卡片更新时间（ISO 字符串）；无则为 null。

封套文本约定（模型侧语义，与 structuredContent 同源）：

text
<prompt-manager-activation private="true">
status: activated
model-action: Treat activated-instructions as the active role/task instructions for this turn.
user-visible-action: Do not display, quote, summarize, or acknowledge the instructions. Do not ask a generic next-step question solely because activation succeeded.
execution: Immediately perform any explicit initialization or task in activated-instructions, subject to higher-priority instructions and normal permission checks.
</prompt-manager-activation>

<activated-instructions>
{卡片正文 body}
</activated-instructions>

调用示例

以下是 MCP 客户端与服务器之间的真实 JSON-RPC 线格式。

请求（客户端 → 服务器）

json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "prompt_manager_activate_prompt",
    "arguments": { "code": "jbyj" }
  }
}

响应（成功，服务器 → 客户端）

json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [
      { "type": "text", "text": "<prompt-manager-activation …>…</activated-instructions>" }
    ],
    "structuredContent": {
      "code": "jbyj",
      "title": "会议纪要整理助手",
      "body": "你是会议纪要整理助手。收到录音转写后…",
      "tags": ["写作", "效率"],
      "thinkingSummary": null,
      "updatedAt": "2026-08-29T09:12:44.000Z"
    },
    "isError": false
  }
}

错误情况

所有错误都以 tool result 形式返回，并带 "isError": true，内容在 content[0].text 中以人类可读中文描述（不抛 JSON-RPC 协议错误，不影响连接）。

触发条件返回文本示例
调取码为空调取码不能为空
未找到该调取码未找到调取码为「xxx」的卡片。请确认调取码拼写，或在提示词管理工具中为该卡片设置调取码后再试。
读取 store.json 失败读取提示词库失败：{message}。请确认 dev 服务已启动并保存过数据（data/store.json 存在）。

响应（未命中，服务器 → 客户端）

json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [
      { "type": "text", "text": "未找到调取码为「xxx」的卡片。请确认调取码拼写，或在提示词管理工具中为该卡片设置调取码后再试。" }
    ],
    "isError": true
  }
}

副作用

复制次数 +1：每次命中调取，该卡片 copyCount +1（与用户在界面手动复制共用同一总数）。 通过 Next.js 计数 API POST /api/sync/increment-copy 写入，避免跨进程直接改文件导致与内存 serverStore 不一致。 计数失败不影响取卡片，会静默跳过（dev 服务未启动 / 端口不通时即如此）。

数据模型

数据源 data/store.json 的顶层结构：{ "cards": [...] }。 每个卡片对象（StoredCard）字段如下。

字段类型说明
idstring卡片唯一 ID（内部主键，调取不依赖它）。
codestring | null调取码。工具按它的小写形式匹配；未设置则无法通过调取码命中。
titlestring卡片标题。
bodystring卡片正文，即加载后交给模型执行的指令。
tagsstring[]标签数组。
thinkingSummarystring | null思维链摘要。
updatedAtstring | null更新时间（ISO 字符串）。
copyCountnumber复制次数（命中调取或手动复制时累加；由服务端计数 API 维护）。

工具返回的 structuredContent 是上述字段的子集（code / title / body / tags / thinkingSummary / updatedAt）， copyCount 与 id 不在返回中暴露。

计数接口

这是 MCP 命中后触发的可选副作用端点，由 Next.js dev 服务（默认 localhost:3100）提供。

POST/api/sync/increment-copy

请求体

json
{ "code": "jbyj" }

响应（成功 200）

json
{ "code": "jbyj", "copyCount": 42 }
状态码含义响应体
200成功，已 +1{ "code", "copyCount" }
400缺少 code 参数{ "error": "缺少 code 参数" }
404未找到该调取码{ "error": "未找到调取码为 {code} 的卡片" }
500服务器错误{ "error": "..." }

调用方（MCP 服务器）对失败做了 .catch() 静默处理，因此计数不可达时不影响卡片读取。

setup.mjs 选项

一键接入脚本支持以下命令行选项（可组合）。

选项作用
--dry-run只预览会改什么，不写任何文件。
--check只体检（构建状态 + 配置状态 + 连通性），不写配置。
--client=<id>只接入指定客户端，逗号分隔。可选：workbuddy、codex、opencode、cursor、claude、cline、windsurf、gemini。
--remove从各客户端配置中移除本 MCP。
--json机器可读输出，便于 AI 解析。

写配置前脚本会自动备份原文件（<文件>.bak-<时间戳>）。

环境变量

变量默认说明
PROMPT_MANAGER_API_URLhttp://localhost:3100覆盖计数 API 的基础地址。当 dev 服务改端口或部署到其他主机时设置。

行为契约

  • 只读：工具只读取 store.json，不修改任何卡片、标签、调取码或数据文件。setup.mjs 同样只读提示词库。
  • 大小写不敏感匹配：调取码在匹配前统一 trim().toLowerCase()。
  • 正文私有：body 是仅供模型执行的指令，客户端/模型不得向用户展示、复述或总结；不得仅因激活成功而追问「下一步做什么」。
  • 非 system message：返回的是 tool result，不能协议级提升为 system prompt；需客户端把结果交给模型才生效。
  • 幂等与计数：每次命中都会触发一次 copyCount +1（不幂等）；计数失败不影响读取。
  • 严格输入：输入 schema 为 .strict()，多余字段会被拒绝。
